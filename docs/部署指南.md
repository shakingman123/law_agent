# 法律文书 Agent · 部署指南

> 面向运维/部署人员。目标平台：Linux 服务器（Ubuntu 20.04+ / CentOS 8+）。架构为 **Nginx 反向代理 + uvicorn 后端 + 静态前端**。

---

## 架构总览

```
浏览器 ──https──► Nginx(:443)
                    ├─ /          → 前端静态文件 (dist/index.html, SPA)
                    ├─ /api/*     → uvicorn 后端 (:8000)
                    └─ /ws/*      → uvicorn 后端 (:8000, WebSocket)
```

- 前端经 `npm run build` 产出 `dist/`，由 Nginx 作为静态资源服务。
- 前端 `request.ts` 的 `baseURL` 默认 `/api`（相对路径），无需额外配置即可走 Nginx 反代。
- `vite.config.ts` 的 proxy（→ localhost:8000）仅开发环境生效，生产环境由 Nginx 接管，无需修改。
- 后端 `app.main:app` 启动时自动 `Base.metadata.create_all` 建表，并播种默认 prompts/模板，无需手动建库。

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Python | 3.10+ | pydantic-settings v2 / langgraph 要求 |
| Node.js | 18+ | 前端构建 |
| Nginx | 任意稳定版 | 反向代理 + 静态服务 |
| SQLite | 系统自带 | 默认数据库；多用户高并发建议换 PostgreSQL |

可选外部服务（按需启用，不装也可运行核心功能）：

| 服务 | 用途 | 不启用的影响 |
|---|---|---|
| Qdrant | 法律检索 RAG（法条/判例/观点） | 法律检索功能不可用，对话撰写不受影响 |
| MinIO | 对象存储（文档云盘） | 文件落到后端本地 `uploads/` 目录 |
| ClamAV | 上传文件病毒扫描 | 跳过病毒扫描 |

## 1.5 服务器环境准备（裸机首次）

在 clone 代码、建 venv **之前**，先在服务器上装好 Python / Node / Nginx / Git。

### Ubuntu / Debian

```bash
# —— 基础工具 ——
sudo apt update
sudo apt install -y git build-essential

# —— Python 3.10+ ——
# Ubuntu 22.04 自带 python3 即 3.10，直接装即可：
sudo apt install -y python3 python3-venv python3-pip
# 若是 Ubuntu 20.04（自带 3.8 偏旧），用 deadsnakes PPA 装 3.10：
#   sudo apt install -y software-properties-common
#   sudo add-apt-repository -y ppa:deadsnakes/ppa
#   sudo apt install -y python3.10 python3.10-venv python3.10-distutils
#   之后 venv 命令改为：python3.10 -m venv .venv

# —— Node.js 18+（用 NodeSource 源，避免 apt 的旧版）——
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo bash -
sudo apt install -y nodejs

# —— Nginx ——
sudo apt install -y nginx

# —— PostgreSQL 驱动（若 DATABASE_URL 用 postgresql://，venv 里也要有 psycopg2）——
# 部署到后端 venv 后执行：pip install psycopg2-binary
```

### CentOS / RHEL / Rocky

```bash
sudo dnf install -y git gcc make
sudo dnf install -y python3 python3-pip      # CentOS 8+ 自带 3.6/3.9，若 <3.10 需另装
# Node.js 18+
curl -fsSL https://rpm.nodesource.com/setup_18.x | sudo bash -
sudo dnf install -y nodejs
sudo dnf install -y nginx
```

验证：
```bash
python3 --version    # ≥ 3.10
node --version       # ≥ 18
nginx -v
git --version
```

> 装完系统依赖后，再进入下方 §2 克隆代码、§3 建虚拟环境。

## 3. 后端部署

```bash
cd /opt/law_agent/backend

# 1) 虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 2) 安装依赖
pip install -U pip
pip install -r requirements.txt
# PostgreSQL 驱动（requirements.txt 未含；DATABASE_URL 用 postgresql:// 时必需）
pip install psycopg2-binary

# 3) 配置环境变量（从示例复制后修改）
cp .env.example .env
vi .env
```

### `.env` 必须修改的项

```env
# —— 数据库 ——
# 单机小规模用 SQLite 即可；多用户建议 PostgreSQL
DATABASE_URL=sqlite:///./law_agent.db
# PostgreSQL 示例：
# DATABASE_URL=postgresql+psycopg://lawuser:你的密码@127.0.0.1:5432/law_agent

# —— 安全密钥（必须换为强随机值）——
SECRET_KEY=<运行 openssl rand -hex 32 生成>
LLM_ENCRYPTION_KEY=<运行下方命令生成 Fernet key>
#   python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

# —— CORS（同源反代下可不配，设上更稳妥）——
CORS_ORIGINS=https://你的域名

# —— 对话状态持久化（默认 memory 会在重启后丢失，生产务必改）——
CHECKPOINTER_TYPE=sqlite

# —— 平台兜底 LLM（生产留空，由管理员在 UI 配置公司 Key）——
PLATFORM_LLM_API_KEY=
```

> 如启用 Qdrant/MinIO/ClamAV，同步修改 `QDRANT_URL`、`MINIO_*`、`CLAMAV_*` 等项，详见 `.env.example` 注释。

### 验证后端可启动

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
# 看到 "Uvicorn running on http://127.0.0.1:8000" 即正常，Ctrl+C 退出
```

## 4. 前端构建

```bash
cd /opt/law_agent/frontend

# 安装依赖（首次）——必须包含 devDependencies！
# tsc / vite / @vitejs/plugin-react 都在 devDependencies，构建期需要它们。
# 若服务器环境变量 NODE_ENV=production，npm install 会自动跳过 devDependencies
# 导致 npm run build 报 "tsc: not found"。--include=dev 强制装全，规避此坑：
npm install --include=dev

# 生产构建，产物输出到 frontend/dist
npm run build
```

> 常见错误 `sh: 1: tsc: not found` = devDependencies 没装。检查 `echo $NODE_ENV`，
> 若为 `production`，改用 `NODE_ENV=development npm install` 或上面的 `--include=dev`。

构建产物为纯静态文件，由 Nginx 托管 `dist/`，**运行时不依赖 `node_modules`**，
也无需 `.env.production`：`request.ts` 的 `baseURL` 默认 `/api`，由 Nginx 反代到后端。

## 5. Nginx 配置

模板见 `deploy/nginx.conf.example`：

```bash
sudo cp /opt/law_agent/deploy/nginx.conf.example /etc/nginx/sites-available/law-agent
sudo vi /etc/nginx/sites-available/law-agent
#   把 YOUR_DOMAIN 改成你的域名或 IP
#   把 root 路径改成 /opt/law_agent/frontend/dist

sudo ln -s /etc/nginx/sites-available/law-agent /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

> 先用 80 端口跑通，再上 HTTPS。

### 关键配置点（已在模板中内置）

- `location /` → `try_files ... /index.html`：SPA 路由刷新回退
- `location /api/` → `proxy_read_timeout 130s`：对齐 LLM 120s 超时，避免长响应被 Nginx 截断
- `location /api/` → `proxy_buffering off`：流式输出实时到达前端
- `location /ws/` → `Upgrade` / `Connection` 头：WebSocket 升级
- `client_max_body_size 50m`：文书/证据附件上传体积

## 7. 进程守护（systemd）

让后端开机自启、崩溃自动拉起。创建 `/etc/systemd/system/law-agent.service`：

```ini
[Unit]
Description=Law Agent Backend (uvicorn)
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/law_agent/backend
EnvironmentFile=/opt/law_agent/backend/.env
ExecStart=/opt/law_agent/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=on-failure
RestartSec=5
# 生产环境不要加 --reload

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data:www-data /opt/law_agent/backend
sudo systemctl daemon-reload
sudo systemctl enable --now law-agent
sudo systemctl status law-agent      # 查看运行状态
sudo journalctl -u law-agent -f      # 实时查看日志
```

> 注意：`www-data` 需对 `backend/uploads/`、`*.db`、`chroma_db/` 有写权限。如用 PostgreSQL 则无需写本地 db 文件。

## 9. 运维要点

- **日志**：后端 `journalctl -u law-agent -f`；Nginx `/var/log/nginx/access.log`、`error.log`。
- **数据库备份**（SQLite）：定期 `cp law_agent.db law_agent.db.bak`；PostgreSQL 用 `pg_dump`。
- **上传文件**：`backend/uploads/` 目录需随数据库一起备份。
- **升级代码**：
  ```bash
  cd /opt/law_agent && git pull
  cd backend && source .venv/bin/activate && pip install -r requirements.txt
  cd ../frontend && npm install && npm run build
  sudo systemctl restart law-agent
  ```
- **更换/添加 LLM**：管理员在「设置 → 模型与 API」直接配置，无需改后端 .env。

## 10. 纯 HTTP / 仅 IP 部署（简化版）

如暂无域名、不上 HTTPS，Nginx 只保留 80 端口 server 块即可：

```nginx
server {
    listen 80;
    server_name _;                 # 接受任意 Host
    root /opt/law_agent/frontend/dist;
    index index.html;
    client_max_body_size 50m;

    location / { try_files $uri $uri/ /index.html; }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 130s;
        proxy_buffering off;
    }

    location /ws/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}
```

后端 `.env` 的 `CORS_ORIGINS` 设为 `http://你的服务器IP`。
